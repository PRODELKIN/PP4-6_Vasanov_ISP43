# Отчёт о тестировании LibraryApp

## Объект тестирования

LibraryApp - консольное приложение на C# с целевой платформой .NET 8 для учёта книг. Класс Book содержит идентификатор, название, автора и признак доступности книги. Класс Library хранит список книг и предоставляет методы добавления, поиска, выдачи и возврата. В Main выполняются примеры операций с выводом результатов в консоль.

## Методика тестирования

Использовались ручное тестирование, отладка в Visual Studio и статический анализ кода.

При ручном тестировании проверялись обычные операции выдачи и возврата, выдача отсутствующей книги, повторная выдача и возврат невыданной книги. Каждый ошибочный сценарий запускался отдельно с исходными данными, соответствующими его условиям.

Для отладки устанавливались точки останова в BorrowBook, ReturnBook и FindBook. Применялось пошаговое выполнение F10 и F11. В окнах «Локальные» и «Контрольные значения» отслеживались id, book и IsAvailable. Результаты до и после исправлений фиксировались скриншотами.

Для статического анализа включены анализаторы .NET и генерация XML-документации. Изучались предупреждения в окне «Список ошибок», проверялись именование, назначение и длина методов, проверки входных ситуаций и обработка ошибок. После добавления XML-комментариев выполнялась повторная сборка.

## Результаты инспекции кода

1. Обнаружено отсутствие XML-документации публичных классов Book и Library, свойств Book и публичных методов Library. После включения генерации документации получено 10 предупреждений CS1591. Добавлены комментарии summary. Повторная сборка текущего проекта завершилась с 0 ошибками и 0 предупреждениями.
2. Имена классов, методов и свойств соответствуют PascalCase. Имена параметров и локальных переменных соответствуют camelCase. Нарушений не обнаружено.
3. Методы небольшие и выполняют отдельные задачи. Дополнительное разделение методов не требуется.
4. Пустые блоки catch и перехват всех исключений отсутствуют. В BorrowBook ошибочные ситуации обрабатываются проверками с выводом сообщения и выходом из метода.
5. XML-комментарии методов краткие. Рекомендуется дополнить их тегами param, а описание FindBook - тегом returns с указанием возможности возврата null. Отсутствие этих тегов в текущих комментариях summary не вызывает предупреждений CS1591.

## Итоги

В ходе отладки выявлены три дефекта.

XML-документация добавлена. Текущий проект собирается без ошибок и предупреждений. Отсутствие предупреждений компилятора не означает отсутствия логических дефектов.

В проекте LibraryApp автоматизированные тесты отсутствуют; процент покрытия кода не измерялся. Проверки выполнялись вручную и с помощью отладчика.
